# 10 — BepInEx Detection

## Где (файл + метод/адрес)
- Сборка: RustSecure.Core.dll
- Файл: `ERRORREFTOINVALIDTYPELIBAllowUnassigned/BepInExDetector.cs`
- Строки: [752280850] `Обнаружен BepInEx. Модули локально в папке: `, далее hash256 и размер
- Обфускация: Agile.NET

## Как работает

### Методы класса BepInExDetector

1. **StartMonitoring()** — запускает периодическое сканирование.

2. **ScanOnce()** — одиночный скан:
   - Ищет папку `BepInEx` в директории игры: строка `BepInEx folder found: `
   - Сканирует содержимое папки

3. **SnapshotLoadedModules()** — снимок загруженных .NET сборок:
   - Проверяет все загруженные модули на принадлежность к BepInEx
   - Использует `AppDomain.CurrentDomain.GetAssemblies()`

4. **BuildDetectionInfo()** — формирует строку детекции:
   - Путь к папке BepInEx
   - SHA256-хэш модулей (через **ComputeSha256()**)
   - Размер файлов в КБ [752280847] ` кб`, [752280844] `0 кб`

5. **OnDetection** — событие, которое уведомляет оркестратор при обнаружении.

### Строка детекции (русский язык)
`Обнаружен BepInEx. Модули локально в папке: {0} (hash256 - {1}, {2}, его вес - {3})`

### Обработка ошибок
`BepInEx module scan failed: ` — при ошибке сканирования.

## Как обойти

### Вариант A — Патч StartMonitoring() (рекомендуется)
Заменить тело `StartMonitoring()` на:
```
ret
```
Мониторинг никогда не запустится.

### Вариант B — Патч ScanOnce()
Заменить тело `ScanOnce()` на:
```
ret
```
Одиночные сканирования тоже будут пропускаться.

### Вариант C — Патч OnDetection event
Найти поле `OnDetection` (event delegate) и обнулить его вызов. Даже если детекция произойдёт, событие не будет отправлено.

### Вариант D — Подмена пути поиска
Найти `ldstr "BepInEx"` (имя папки) и заменить на несуществующее имя, напр. `ldstr "XXXXXXXX"`. Детектор будет искать не ту папку.
