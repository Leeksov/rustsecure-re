## 1. ЧТО ЭТО ЗА ПРОЕКТ

Мы реверсим **RustSecure** — античит-систему:

- `RustSecure.exe` — загрузчик-стаб (managed .NET, обфусцирован).
  Скачивает с сервера два payload'а, проверяет лицензию/HWID, инжектит DLL в Rust.
- `RustSecure.Core.dll` — **Core payload** (managed .NET DLL), скачивается с сервера.
  Это сам «движок» античита, ~19 МБ, сильно обфусцирован.
- Серверная часть (backend) — ASP.NET Core (Kestrel) за Caddy.

### Целевые файлы (относительные пути)

```
./samples/RustSecure.exe          # загрузчик-стаб
./samples/RustSecure.Core.dll     # Core payload (выдан клиентом)
./re_analysis/                    # все скрипты и отчёты
./re_analysis/payloads/           # скачанные ответы сервера
```

## 2. ЧТО УЖЕ СДЕЛАНО (кратко)

1. **Определён обфускатор**: Agile.NET / CliSecure-семейство.
   - VM-расшифровка строк (82-опкодная VM + 25-опкодная VM).
   - «распил» методов на тысячи мелких стабов (метод-сплиттинг).
   - переименование в мусорные имена.
   - данные хранятся в `FieldRVA` (bytecode / таблицы).
2. **Найдено 112 зашифрованных строк** (AES-256-CBC, base64) по файловому смещению `0x2d0385`
   в `RustSecure.exe` — это пароли/URL/бэкенд-ссылки.
3. **Полностью разобран формат байткода** 82-опкодной VM (метод 0x89E) и 25-опкодной VM (метод 0x8A2).
4. **Определены роли полей FieldRVA** (см. 01-файл).
5. **Найден серверный API** и его схема шифрования (см. 02-файл).
6. **Скачаны ответы сервера** (core/native зашифрованы, manifest/checksum — SHA-256).

## 3. ПООЧЕРЁДНЫЙ ПЛАН ДЕЙСТВИЙ

### Этап 1 — Закрыть криптографию строк в RustSecure.exe (задача A→B)
1. Прочитать `01_Анализ_loader_RustSecure_exe.md` (там весь контекст VM).
2. Запустить готовый скрипт `xor_bc.py` — проверить гипотезу XOR-деобфускации байткода
   `FLD[1431]` ключом `37 ad a0 fe` (и реверсом `fe a0 ad 37`).
   - Если появятся «чистые» инструкции VM (опкоды 1..82 с малыми операндами) — ключ найден.
3. Если XOR не сработал — изучить паттерн «удвоенных байт» (`24 24`, `1a 1a`, `7c 7c`, `61 61`)
   в байткоде и восстановить реальную трансформацию.
4. Извлечь 32-байтный ключ + 16-байтный IV, расшифровать 112 строк AES-256-CBC.
   - Готовые скрипты: `bruteforce_key.py` (перебор окон), `crack_strings.py`, `decrypt_test.py`.

> **ЦЕЛЬ этапа 1**: получить открытый текст 112 строк. Среди них — `sharedSecret`,
> URL бэкенда, ссылка на Telegram, пароли.

### Этап 2 — Расшифровать серверные payload'ы (задача C→D)
1. Прочитать `02_Анализ_сервер_API.md`.
2. Взять `sharedSecret` из этапа 1.
3. Восстановить вывод ключа (KDF) из методов загрузчика:
   `DecryptPayload` (0x2FD), `ComputeSignature` (0x2FE), `HmacSha256` (0x300/0x301).
4. Проверить HMAC (`X-Rs-Mac`) и расшифровать `payloads/core.enc` + `payloads/native.enc`
   (AES-256-CBC, IV в заголовке `X-Rs-Iv`, ключ = KDF(sharedSecret, nonce, ts)).

> **ЦЕЛЬ этапа 2**: получить два DLL в открытом виде (Core = managed, Native = нативный).

### Этап 3 — Разобрать RustSecure.Core.dll (задача E)
1. Прочитать `03_Анализ_Core_dll.md`.
2. Отделить мусор от реальной логики (84 077 методов — это метод-сплиттинг).
3. Найти точки входа/экспорты, HWID-проверку, анти-отладку, инжект-логику.

### Этап 4 — Обход (задача F)
1. Прочитать `04_Методы_защиты_и_обход.md`.
2. Реализовать обход каждого метода (патчи или обход через реальный sharedSecret).

## 4. ИНСТРУМЕНТАРИЙ (что установлено и работает)

- **Python 3** с библиотеками: `dnfile`, `dncil`, `pycryptodome` (Crypto).
- Все скрипты лежат в `re_analysis\*.py` и уже отлажены.
- Ключевые API (запомнить, чтобы не наступить на грабли):
  - `dnfile.dnPE(path)` → `pe.net.mdtables` (таблицы метаданных).
  - `pe.net.mdtables.FieldRva.rows` → `r.Field.row_index`, `r.Rva`.
  - `pe.get_offset_from_rva(rva)` → файловое смещение.
  - Размер FieldRVA = разница между соседними RVA.
  - IL-токены: MemberRef=0x0A, MethodDef=0x06, Field=0x04, TypeRef=0x01, string=0x70.
  - У тела метода (`dncil.CilMethodBody`): `b.max_stack` (НЕ `maxstack`), `b.instructions`.
    Атрибута `b.locals` нет.
  - У `TypeDef` строки: `r.TypeName`, `r.TypeNamespace` (НЕ `r.Name`).
  - `md.UserStrings` нет — строки из `#US`-кучи доставать через `pe.net.user_strings` /
    `md.UserString` отсутствует (искать актуальный атрибут dnfile).
