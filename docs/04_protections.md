# 04 — МЕТОДЫ ЗАЩИТЫ И ОБХОД

Цель: перечислить **все** методы защиты, указать **в каком файле/методе** каждый находится,
**как** работает и **как обойти**. Это основа для быстрого обхода.

> Легенда расположения:
> - **Загрузчик** = `RustSecure.exe` (стаб, точка входа `Main` в классе `MeterFrameIntervalManager`).
> - **Core** = `RustSecure.Core.dll` (managed payload).
> - **Native** = нативный payload (`/api/loader/native`).
> - **Сервер** = backend ASP.NET Core (`rustsecure.ru`, `2.26.50.179:5003`).

---

## 1. Обфускация (Agile.NET / CliSecure)

- **Где**: весь код, обе сборки (RustSecure.exe и RustSecure.Core.dll).
- **Как**: VM-расшифровка строк (82-опкодная + 25-опкодная), метод-сплиттинг
  (84 077 методов в Core), мусорные имена, данные в FieldRVA.
- **Обход**: не обходится — это препятствие анализу, а не защита выполнения.
  Решение = деобфускация (восстановление строк и имён) как описано в 01/03-файлах.
  Для патча достаточно деобфусцировать строки и найти целевые проверки по именам.

## 2. Single-instance мьютекс

- **Где**: загрузчик, `Main` (шаг 2 потока).
- **Как**: `CreateMutex`/named mutex; повторный запуск закрывается.
- **Обход**: игнорировать (нужен один запуск), либо закрыть существующий мьютекс /
  патчить проверку, если надо несколько инстансов.

## 3. PrivacyConsentForm (форма согласия)

- **Где**: загрузчик, `Main` (шаг 3).
- **Как**: модальная форма; без согласия — выход.
- **Обход**: патч — пропустить показ формы / всегда «согласен». При чистом обходе
  вызвать следующий шаг напрямую.

## 4. Проверка VC++ redistributable

- **Где**: загрузчик, `Main` (шаг 4).
- **Как**: проверка наличия рантайма VC++; нет — выход/установка.
- **Обход**: патч — пропустить проверку (или установить redist).

## 5. Анти-отладка / анти-VM

- **Где**: загрузчик `Main` (шаг 5) + скорее всего Core.
- **Как**: типичные проверки — `IsDebuggerPresent`, `CheckRemoteDebuggerPresent`,
  `NtQueryInformationProcess` (ProcessDebugPort), тайминги, детект VM
  (имена вендоров CPU/BIOS, `rdtsc`, VM-артефакты).
- **Обход**: патч возвращаемых значений на «не отлаживается / не VM», либо запуск под
  маскировкой (ScyllaHide и т.п.). При статическом патче — NOP'нуть ветки или
  заставить проверки возвращать false.

## 6. HWID-лицензирование

- **Где**: загрузчик и/или Core; серверная валидация.
- **Как**: сбор HWID (серийники железа, MAC, VolumeID, CPU-ID → хэш), отправка на сервер,
  проверка лицензии в ответе. Без валидной лицензии payload не выдается / не запускается.
- **Обход**:
  1. **Серверный**: расшифровать `sharedSecret` → самому запрашивать payload по API
     (см. 02-файл) — легитимный обход без патча HWID.
  2. **Клиентский**: патч — заставить проверку HWID/лицензии возвращать `true`,
     пропустить валидацию ответа сервера.

## 7. Шифрование и аутентификация payload'ов (AES-256-CBC + HMAC-SHA256)

- **Где**: сервер + загрузчик (`DecryptPayload` 0x2FD, `ComputeSignature` 0x2FE,
  `HmacSha256` 0x300/0x301).
- **Как**: payload шифруется AES-256-CBC (ключ = KDF(sharedSecret, nonce, ts)),
  подписывается HMAC-SHA256; клиент проверяет MAC и расшифровывает.
- **Обход**: получить `sharedSecret` из загрузчика (расшифровка 112 строк) →
  расшифровать payload'ы офлайн. Это **самый чистый обход** — не требует патча,
  даёт открытые DLL для анализа.

## 8. Закрытие процесса Rust (`AssessFrameQuality`)

- **Где**: загрузчик, `Main` (шаг 7).
- **Как**: перед запуском/инжектом принудительно закрывает уже запущенный Rust
  (чтобы инжект прошёл в свежий процесс).
- **Обход**: это не защита; учитывать при анализе (программа убивает игру).

## 9. Инжект (`ForecastFrameLoad.InjectNativeAndRunCore`)

- **Где**: загрузчик, `Main` (шаг 10); Native payload.
- **Как**: после запуска Rust и ожидания модуля — инжект Native + запуск Core
  (через `CreateRemoteThread` / `WriteProcessMemory` / manual map).
- **Обход**: не защита, а сама суть программы. Нужно для понимания, что Core.dll
  исполняется внутри Rust.

## 10. Дополнительные защиты в Core.dll (TBD — выяснить по мере анализа)

- Скорее всего: проверка целостности (`/api/manifest/checksum`), анти-тампер,
  проверка подписи/сборки, обфускация строк, возможно драйверная связь (kernel).
- **Статус**: выясняется (см. 03-файл). Заполнить после деобфускации Core.

## ИТОГОВЫЙ ПЛАН ОБХОДА (краткий)

**Путь A (рекомендуемый, чистый):**
1. Расшифровать 112 строк в RustSecure.exe → получить `sharedSecret`.
2. По заголовкам API (X-Rs-Iv/Nonce/Ts/Mac) + KDF из методов 0x2FD/0x2FE/0x300/0x301
   расшифровать core/native payload'ы офлайн.
3. Анализировать открытые DLL статически.

**Путь B (патч клиента):**
1. Деобфусцировать строки и найти проверки (HWID, license, anti-debug/VM).
2. Патчить IL так, чтобы проверки возвращали успех.
3. Переподписать/запустить изменённую сборку (или загрузить свой payload).

> ВАЖНО: бинарь не запускать. Обход = статический патч + офлайн-расшифровка,
> без исполнения вредоносного кода.
